# Maple Layers: handoff notes for agents

Last updated 15/10/2026. Read this first, then `README.md` for the commands.

## What this is
A prototype: a one-screen website where a user builds a MapleStory (Classic World) avatar by picking one item per category and recolouring it.

- **Character:** skin, face, hair. Hair and face are split Male/Female, and each style has all its colour variants (8 hair colours, 9 eye colours).
- **Wearables:** hat, face accessory, eye decoration, earrings, overall, top, bottom, gloves, shoes, cape, weapon, ring. Each worn item gets **Tone / Chroma / Brightness** sliders, per category.
- **Item list source:** the Nexon "Founder's Access Cash Shop" post (the user pasted the item names; the page itself is client-rendered and cannot be fetched). Names live in `data/names.txt` and `data/hairface.txt`.
- **Sprite source:** the public maplestory.io API (the data behind maplestory.wiki), GMS v110 with v210.1.1 as a fallback for newer items. Sprites are **downloaded and stored locally** (`public/sprites`, about 6 MB). **Everything is stored locally** (released and datamine hair/faces, wearables, skins, map): the running app makes no API calls (superseded the earlier live-fetch design, see the 19/10/2026 note at the end).
- **Not for release as-is:** MapleStory art belongs to Nexon. Keep the repository private; anything public needs the right sign-off first.

Stack: Vite 5, vanilla JS (no framework), `pngjs` for scripts, `puppeteer-core` for browser tests (needs Google Chrome at `/Applications/Google Chrome.app`, path hard-coded in `scripts/ui-test.mjs` and `scripts/layout-check.mjs`).

**No version control:** this folder is not a git repository, and `src/main.js` was once wiped by a bad edit and rebuilt from the session. Run `git init` and commit before large changes.

## Run it
    npm install
    npm run dev            # http://localhost:5173
    node scripts/colour-check.mjs          # colour maths, no server needed
    node scripts/ui-test.mjs               # browser test, needs the dev server running
    node scripts/layout-check.mjs          # layout at 3 window sizes, needs the dev server running

## How it fits together
`data/*.txt` (names) → `build-manifest.mjs` → `data/items.json` + `data/report.json` → `download.mjs` (part sprites), `download-skins.mjs` + `place-skins.mjs` (body parts), `download-icons.mjs` (wearable icons) → `build-catalog.mjs` → **`public/catalog.json`**, the only data file the app reads.

Files you edit by hand (then run `node scripts/build-catalog.mjs`):
- `data/names.txt` wearable names. `data/hairface.txt` hair/face names under `# hair male` style headers (gender comes from the Nexon post's own lists).
- `data/rules.json` layer rules (see below). `data/placeholders.json` items that could not be found.

App code: `src/main.js` (state, UI, canvas drawing), `src/compose.js` (layer compositing and colour maths), `src/style.css`.

Legacy, safe to ignore or delete: `scripts/lookup.mjs`, `scripts/calibrate.mjs`, `data/matched*.json`, `data/unmatched*.json` (early exploration, superseded by `build-manifest.mjs`).

## Facts worth knowing (hard to rediscover)
- **Placement:** every part sits at `anchor - origin - mapOffset`. Anchors in skin-PNG pixels: brow (17,14), navel (17,45), hand (29,51). Calibrated against real API renders; see `scripts/calibrate-anchors.mjs`.
- **Layer order** comes from the game's own table, `data/zmap.json` (back to front). Each part carries its game layer name, for example `accessoryFaceBelowFace` (the blush sits behind the eyes) and `weapon` (between body and arm/hand).
- **Skin** is real separate parts (body, arm, head) from the raw WZ browser endpoint `https://maplestory.io/api/wz/GMS/110/Character/...`. The head's attachment points are not readable there, so `place-skins.mjs` locates each part inside the API's flattened skin render (`data/skin-renders/`). The part-built skin matches that render with 0 differing pixels.
- **Hats flatten hair:** a hat declaring slot `H1` hides the hair layer `hairOverHead` (rule in `data/rules.json`). `H5` hid nothing in tests.
- **Overall vs top/bottom:** equipping an overall removes top and bottom, and the reverse.
- **Same zoom and card size everywhere:** every card in the catalogue and the colour previews in the Equipped panel is the same component (the small tiles at the top of that panel are not: see below), 5 per row with an 8px gap both sideways and up and down (`.grid`: `repeat(5, minmax(0, 1fr))`, `gap: 8px`). The two halves of the page are exactly equal in width (`.app`: `1fr 1fr`, max 1360px) and their grids have the same inner width (the left panel's padding is 12px to match the right panel's padding plus scroll padding), so the cards come out the same size on both sides (about 121px wide at a 1440px window, 113px at 1280px; art `ART_H` 84px tall plus a one-line label, 107.6px tall in all; a name too long for one line is cut off with an ellipsis and its full name is the card's tooltip, which affects about 10 of the 135 names). Skin, face and hair cards use `VIEW` through `paintFocus`, so they share one whole-number zoom (3 device pixels per sprite pixel at 1.5 css px on a 2x screen), are never CSS-scaled and show the same crop. The small tiles at the top of the Equipped panel (`equippedCard`, class `mini`) are 68px wide previews: the face alone and the hair alone at `MINI_VIEW` (1 css px per sprite px, so the whole head, still a whole-number zoom; `centre: true` aims the crop at the middle of the pixels drawn around the head, so each picture sits in the middle of its tile), item icons at natural size, a ring as its tag or bubble shrunk to fit; each has only its category underneath (Face accessory shows as "Face" and Eye decoration as "Eye", `SHORT_LABEL`), and the full name and colour as the tooltip. The left half has the preview across its full width (a short box, 240px tall) and the Equipped panel below it. The Download PNG and Reset all buttons were removed; `exportPng()` is still in `src/main.js` but not wired to anything.
- **Crisp pixels:** sprite pixels are drawn as whole device pixels (`paintFocus` in `src/main.js`), so scales like 1.5x and 2.5x CSS px are used on 2x screens. Do not CSS-scale canvases by non-whole factors. Every thumbnail and the preview compose into a canvas of their own (`withScene` hands `paint(buf, source)` a fresh `source` canvas); do not go back to one shared scratch canvas (see the WebKit note at the end).
- **Colour sliders** (the game's numbers, all start at 0 = the item's own colours; implemented in `adjustColour`, `src/compose.js`): Tone 0 to 359, Chroma and Brightness -99 to +99. See the Dye note at the end for the maths.
- **Placeholders** (dashed "PLACEHOLDER" cards) and **CHECK** badges (yellow) are generated by `build-catalog.mjs` so unresolved items are visible and get fixed. A "!" on a tab means that tab has placeholders.

- **Skin names** are in `SKIN_NAMES` (`src/main.js`, from MeowDB: Light 0, Tan 1, Brown 2, Pale 3, Ashen 4, Green 5, Pink 10, Warm 11). Tones 9, 12 and 13 are downloaded but not in Classic, so they are hidden. The Skin tab shows cards (same crop as face and hair) on the current face and hair.

- **Pinned hair** (`data/pinned.json`, applied by `scripts/add-pinned.mjs` after `build-manifest.mjs`, then `download.mjs` and `build-catalog.mjs`): Toben, Zeta, Unkempt, Shaved (male starters, ids 30000 to 30030), Cutie Hair (female, 31000; the older game versions call it "Sammy"), Edgy Hair (female, 31040) and Rockstar Hair (female, 31050; older versions call it "Connie") — the three female creation hairs per meowdb.com/msclassic/beauty and mapleclassic.wiki — Medium Cornrows, Chestnut (30240; the API calls that sprite "Black Monkey", so the art is unconfirmed against Classic), Short Regent Cut (33350 for colour Black: the API calls it "Black Short Flip Cut" but its silhouette matches the other Short Regent colours) and the beginner faces (male 20000 to 20002 with the salon names Defiant, Confident, Prudent Face; female 21000 to 21002 named Motivated Look, Fearful Stare, Leisure Look from the API, so those names are unconfirmed for Classic). Prim Face (female) is also pinned to fill its missing White colour. Male names come from henesys.gg/salon, which has no female list; the female creation hair names come from meowdb.com and mapleclassic.wiki.
- **Order:** every list is sorted lowest id first in `build-catalog.mjs`. Male hair and face follow the Classic salon's ids (`data/salon-order.json`, copied from henesys.gg/salon 16/10/2026, matched by name); everything else (female styles, which the salon page does not list; wearables; skins) uses its own item id.

- **Selection model:** there are no "None" cards. A new character starts with the lowest-numbered skin and no face or hair (`initial()` in `src/main.js` returns `fresh()`); the All/Male/Female picker only filters the lists and never touches selections. (Superseded 18/10/2026: there used to be a default face and hair and a `dirty` flag that swapped them when the picker changed.) Colour is split in two, on purpose:
  - **Selector (right):** the Face and Hair tabs have a colour bar (`renderColourBar`) of rectangular swatches in the game's own picker colours (`HAIR_COLOURS`, `EYE_COLOURS` in `src/main.js`, sampled from the user's screenshots of the in-game pickers: hair 8, eyes 9). Picking a colour redraws every card in that colour (`browse` in `src/main.js`) and does not touch what is worn. A card picked afterwards comes in that colour. Wearables have no list colour; their cards are inventory icons.
  - **Equipped (left, `renderColour`):** shows what is worn as sprites, with the name as a tooltip: the face alone and the hair alone on the skin, then each wearable's icon (a ring shows its tag or bubble). Selecting a tile shows its settings: face and hair show preview cards of the chosen style in every colour (`colourGrid`), a wearable shows Tone/Chroma/Brightness. `configTarget` holds the selected row and follows whatever was last equipped. clicking the selected card (face, hair or any wearable) removes it. One Male/Female switch beside the Character tabs filters both Face and Hair. Colour names are the game's own: hair Black, Red, Orange, Blonde, Green, Blue, Purple, Brown; eyes Black, Blue, Red, Green, Hazel, Sapphire, Violet, Amethyst, White.

## Name tag and chat bubble rings
Six rings (White/Chocolate Label, Ink-and-Wash Name Tag, Kitty Chat, Chocolate Chat, Ink-and-Wash Thought Bubble) draw no avatar sprite. The game builds them from UI pieces, and so does this app (`src/ring.js`), as the maplestudio.app simulators do; meowdb.com instead serves pre-rendered preview PNGs.
- **Name tag:** left end `w`, one-pixel-wide middle `c` repeated to the text width, right end `e`, text in `clr`. **Chat bubble:** nine pieces (`nw n ne / w c e / sw s se`) plus `arrow` (optional `head` on the top edge); the frame is always three edge tiles plus the arrow wide and long text wraps. Each piece has an origin that sits on the layout line.
- **Data (superseded by the 24/10/2026 "Rings rebuilt" entry: the pieces now come from the game files and the codes are the rings' own):** `UI/NameTag.img/<code>` and `UI/ChatBalloon.img/<code>` from the raw WZ endpoint (GMS v150), downloaded by `scripts/download-rings.mjs` into `public/sprites/ring/`. `data/rings.json` lists the rings with their Classic ids (henesys.gg/cashshop) and codes. **The codes are not in any data we have:** Classic reuses ring ids for different rings than GMS, so they were matched by eye against meowdb.com's in-game previews and the KMS names on maplestudio.app, and the result was checked side by side (Label 15, Ink-and-Wash tag 59, Kitty bubble 18, Chocolate bubble 26, Ink-and-Wash bubble 59). White Label Ring has no pieces (the client draws a plain white box with a blue edge, drawn by `drawPlainTag`).
- **App:** two wearable slots, `nameTag` ("Name tag") and `chatBalloon` ("Chat bubble"), so one of each can be worn together. Text is in `state.text` (name for the tag, name and message for the bubble, which reads `name : message`), edited in the tab and in the Equipped panel. The tag hangs under the feet and the bubble sits over the head (`ringLayer`); the preview widens to fit them. The working canvas is now 160x230 with the skin at OY 112 to make room.
- **Fonts:** the game uses Dotum / NEXON Lv1 Gothic, which are not installed here, so text falls back to a system font and looks softer than in game.

## Tested, and how
Run on 15/10/2026: `colour-check.mjs` 17/17 pass; `ui-test.mjs` 29/29 pass (re-run 17/10/2026 after the colour decoupling and the ring effects; the file now has 51 checks, all passing) with no console errors; `layout-check.mjs` shows no page scroll at 1440x800@2x, 1280x720@2x and 1280x720@1x (its `firstRow` figure now counts the Equipped panel's cards, so ignore it; I measured 5 cards per row with 8px gaps in both halves at 1440x800 and 1280x720 at 2x). `verify.mjs` compares my layering with the API's own render (0.0% differing pixels for weapon-only outfits; about 4% for full outfits, mostly because the API renders a blank face).

## What is left
1. **Colour prism accuracy: resolved 17/10/2026.** The user supplied seven in-game screenshots (Tone/Chroma/Brightness readings with the dyed result); the app now uses the game's dye model (see the Dye note at the end). Still open: the palette (hue-band) filter and a colour-series picker are not implemented.
2. **+Chroma has no effect on about half the items** (33 of 68): their sprite colours are already at the sRGB limit (for example pure web colours such as 238,153,0). Not a bug. A possible fix is letting positive chroma also shift lightness toward the most vivid point; not done, needs the user's call.
3. **No placeholders are left.** The six rings are now drawn (see Name tag and chat bubble rings above). **Beetle Long Sleeve** (Classic 1047027) is not in the sprite API, so it uses the API's "Beetle Longsleeve Top" (1042032), which the user confirmed is correct (`STAND_INS` in `scripts/build-manifest.mjs`). **Orange Toy Hammer** (1702010) has no `stand1`, so wearing it puts the whole character in the two-handed pose (`stand2`): `rules.json` `stand2Only` marks it, the catalogue carries `parts2` for skins/hair/face/wearables (`download-skins.mjs stand2`, `place-skins.mjs stand2`, `download.mjs` writes `meta2.json` and `*.2.png`, `ANCHORS2` in build-catalog.mjs: navel 17,45, brow 17,14, hand 22,45), and `buildLayers` uses `parts2` when that weapon is worn. Matches the game's render visually; not pixel-diffed. Other items fall back to their standing parts if they have no stand2 sprite.
4. **No CHECK items left in hair.** Bowl Cut is 3019 (male; 3193 is female and not in Classic). Bed Head Hair (3239) and Prince Cut Hair (3300) were resolved to the earlier id at the user's request via `useEarlierId` in `data/rules.json`; Prince Cut 3306 differs slightly in colours 4 to 7. **Medium Cornrows is pinned to id 30150** (Classic salon list, henesys.gg/salon), but the v110 API names that sprite "Black Dreadlocks", so the art is unconfirmed against Classic.
5. **Open design choices never answered:** whether hair/face thumbnails should also show worn wearables (currently they show skin plus the other of face/hair only, because a hat flattens hair); skin-tone protection for chroma (not added).
6. **Not built, by decision:** an admin panel. The user chose to keep rules as hand-edited files and answer open questions on the backend.
7. **Small gaps:** the extra "ear" body part is omitted (the standard render never draws it); on 1x displays hair thumbnails use 2x and crop a few pixels at the sides.
